# Keeping the matrices current

The lane matrices are data. Updating them never needs a code change.

## The update path, end to end

1. Edit the markdown under `data/lanes/source/` (or drop in a new file generated by
   Claude). The tables are the source of truth for Status and Evidence. Two extra
   sections live at the bottom of each file and are yours to edit too:
   `## Sourcing vocabulary` (keywords) and `## Aliases` (the alternate names the
   grader matches against posting text).
2. Run the sync. It refuses to write anything if any file fails to parse.

   ```
   npm run sync:lanes          # or: python -m resume_gen.lanes sync
   ```

3. Validate. This is what CI would run.

   ```
   npm run validate:data       # or: python -m resume_gen.lanes validate
   ```

4. Restart the app (or `docker compose -f docker/docker-compose.yml up -d --build`).
   The app refuses to boot on a malformed lane file, and prints a warning per lane
   whose markdown has changed since its JSON was generated.
5. Regrade the queue against the new matrices: **Jobs tab, Regrade all**, or
   `POST /jobs/regrade`.

## What changes where

| Change | Edit | Then |
|---|---|---|
| A status flip (held, partial, building, not yet) | the skill's row in the markdown table | sync, validate, regrade |
| A new keyword or alias | `## Sourcing vocabulary` or `## Aliases` | sync, validate |
| A new NOC code | `data/noc.json`, then the lane's NOC map table | sync, validate |
| A new lane 13 | new `lane-13-<slug>.md`, an entry in `data/lanes.index.json` (with `persona`, `links`, `match`), a persona in `data/profile/personas.yaml` | sync, validate |
| A new screening answer | `data/answer-bank.json` (or confirm one in the app; it writes back) | restart |
| An outreach template | `data/outreach-templates.json` | validate, restart |
| A new instruction-set version | bump `version` in `data/lanes.index.json`; add a `data/CHANGELOG.md` entry | sync (stamps every lane), validate |
| A change to the lane file shape | see `data/migrations/README.md` | migration script, schema, converter, version bump |

## Drift

`npm run drift:lanes` compares each lane JSON's recorded source hash with the markdown
on disk. The app runs the same check at boot and exposes it at `GET /lanes/status`.
Drift means one side was edited without the sync; run the sync and the warning clears.

## Nothing in the app edits a Status

There is no UI that changes a skill status. Statuses come from you through the
markdown. If a UI for that is ever built, it must write to the markdown and re-run
the sync, so the files stay the source of truth.
